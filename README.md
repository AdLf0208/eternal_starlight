# Eternal Starlight for Horizon — slice 1

A port of [Eternal Starlight](https://github.com/LeoMinecraftModding/eternal-starlight)
`0.9.1+1.21.1+neoforge` (MIT) to Minecraft Java **26.3** on Horizon.

**What this slice ships:** the **Starlight dimension** exists, is enterable
(`/execute in eternal_starlight:starlight run …`) and generates. Its biome source
reproduces four of the mod's biomes from the jar's own parameter table, its own
noise settings and material rule are carried, and the nine blocks those surfaces
use come with their assets, loot and names. A `/eternal_starlight status`
command reports the dimension, the biome count and the biome at a position.

**What it does not ship** (each is recorded in `notes.md`): the other nineteen
biomes, the mod's structures, plants, ores, trees and decorations, its mobs, its
menus and items, its client effect and sky, and its cave carver.

This is deliberate: the jar is a full dimension mod (791 blockstates, 314 worldgen
JSONs), and the campaign delivers it in slices. Local-only until the maintainer
approves publishing.

```
ports/eternal_starlight/
  horizon-mod.toml   the manifest (api 0.2, side both, the two pins)
  src/lib.rs         the one impl Hooks: registrations and the readout command
  src/runtime.rs     the pure logic and its tests (parameter table, terrain, surface, readout)
  src/table.rs       the jar's parameter rows, generated by tools/gen_table.py
  assets/, data/     the carried content (26.3 formats)
  tools/             carry_content.py, gen_table.py, e2e.sh
  notes.md           scope, inventory, gaps, adaptations, verification
```

## Build and check

The SDK is fetched into `.horizon/sdk/` by any `cargo horizon-mod` command; this
tree already carries a copy at the pin.

```sh
cargo test --offline
cargo clippy --all-targets -- -D warnings
rm -f Cargo.lock && cargo horizon-mod build      # packs eternal_starlight.hmod
cargo horizon-mod check eternal_starlight.hmod
cargo horizon-mod fits eternal_starlight.hmod --build nightly
```

`tools/carry_content.py --check` proves the package still matches the jar (and
that no carried file was altered outside the recorded conversions);
`tools/gen_table.py --check` does the same for the parameter table.

## Licence

MIT, read from the jar's `META-INF/neoforge.mods.toml`; `LICENSE` is the
upstream text and `LICENSE-NOTICE.md` records where it was read. The content
under `assets/` and `data/` is the original's own, converted to 26.3's formats.
